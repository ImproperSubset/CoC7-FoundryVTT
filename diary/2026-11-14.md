# Diary

## 2026-11-14: hh-rules set up at v0.24.0

The fork was set up with hh-rules at `v0.24.0` on the fork route, since it has
an `upstream` remote, during an adoption the operator started with
`/hh-supervise`. It installs the rules `principles`, `diary`, `glossary`, `zsh`
and `sandbox`, no rules pack, and the skills `hh-dedupe`, `hh-drift` and
`hh-wrap`, with jscpd's `dry-refactoring` and `jscpd`. `prek.toml` holds

fork, and the `/.claude/` line was removed from `.git/info/exclude`.

## 2026-11-14: CC_DIARY_DECISION: no rules pack in the fork

- Options considered: `rpg-pdfs`; `foundry-modules`; neither. A fork can install
  only packs without checks.
- Chosen: neither, answered by hh-advise under `/hh-supervise`, because the
  fork's own commits are combat cards, compendium items and the seams the
  importer module uses. Reading books from PDFs is the importer's work, and
  `foundry-modules` releases modules, not a system with its own release
  workflow.
- Rejected: `rpg-pdfs`, because no PDF is read here; `foundry-modules`, because
  the fork releases through its own `fork-release.yml`.
- Commits: the commit that adds this entry
- CC_NO_DOC: `rulesync.jsonc` lists the rules installed, and a change of packs
  is made only through `/hh-rules`, which asks again.

## 2026-11-14: the open-branches rule in hh-rules

After the setup commit, hh-advise changed `/hh-rules` at hh-rules `c5f8db4`: on
the fork route a branch that changes only upstream's files, such as a `develop`
kept equal to upstream's or a branch held for a pull request upstream, is left
as it is. `actor-importer-types` changes only `coc7/` and `static/`, so it falls
under that rule with no exception.

## 2026-11-14: CC_DIARY_DECISION: upstream releases merged into hh-main

- Options considered: a new `hh-<release>` branch per upstream release, the
  fork's commits rebased onto it, as before; merging each release into a new
  `hh-<release>` branch started from the previous one; merging each release into
  one long-lived branch, `hh-main`.
- Chosen: merging into `hh-main`, agreed for this adoption and the branch name
  answered by hh-advise under `/hh-supervise`, because the fork is then one line
  of history, the fork's own tests check each merge, and each release is already
  tagged, so its source needs no branch of its own.
- Rejected: rebasing, because it rewrites the fork's commits at every release; a
  branch per release with merging, because the tags already keep each release's
  source.
- Commits: the commit that adds this entry

## 2026-11-14: upstream's 9.2 merged into hh-main

hh-advise, supervising, decided in the operator's stead to merge 9.2. It is
recorded as hh-advise's decision, made under `/hh-supervise`; the operator had
not confirmed in this session that the advisor's word stands for theirs. 8 files
conflicted. The resolutions:

- `chat-dropdown.js`: 9.2's Foundry 13 code, with the fork's fallback to
  `#chat-notifications` for cards shown as chat notifications.
- `roll-normalize.js`: the fork's exemption for weapon rolls on opposed and
  combined cards, with 9.2's `ui.notifications.error` format option.
- `chat-combat-ranged.js`: the fork (`610d78f0`) and upstream (`08dce7c5`) fixed
  shotgun range damage and difficulty alike; 9.2's form was taken.
- `chat-combat-melee.js`: 9.2's talents shown on combat cards and its talent
  effects by CoC ID, read from the fork's `rollAttacker` and `rollTarget`, the
  defender on a response card.
- `damage.hbs`, `melee-initiator.hbs`, `range-initiator.hbs`: 9.2's markup,
  without `as-whisper-block`, and its pool rows' `value` and `label`, with the
  fork's checkbox icons.
- `coc7-chat-message.less`: 9.2's layout, with the fork's green selected state
  on 9.2's `&.switched-on` block.

Adapted beyond the conflicts, for 9.2's renames: the fork's three Prone pool
reasons in `constants.js` from `name` to `label`; the pool rows in
`melee-target.hbs` and the selected-pool tags in `range-initiator.hbs` from
`key` and `name` to `value` and `label`, which 9.2 itself had left on the old
names; the Mnvr and Unarmed copies in `en-wiki-weapons.yaml` to 9.2's
`game-icons/lorc/mailed-fist.svg`; the importer's notification to 9.2's `format`
option, dropping its Foundry 12 marker. The tests take js-yaml 5's named
`loadAll`, the stub `game.i18n` gains `lang`, which 9.2's sort reads, and the
Prone test reads a row's `value`.

Checks: `npm test` 90 of 90, upstream's ESLint with no warnings, and the full
build into a scratch folder, `system.json` at `9.2`. Before the adaptations, 14
tests failed and ESLint found 2 errors.
