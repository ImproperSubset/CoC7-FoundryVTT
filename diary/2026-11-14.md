## 2026-11-14: hh-rules set up at v0.24.0

The fork was set up with hh-rules at `v0.24.0` on the fork route, since it has
an `upstream` remote, during an adoption the operator started with
`/hh-supervise`. It installs the rules `principles`, `diary`, `glossary`, `zsh`

fork, and the `/.claude/` line was removed from `.git/info/exclude`.

## 2026-11-14: CC_DIARY_DECISION: no rules pack in the fork

- Options considered: `rpg-pdfs`; `foundry-modules`; neither. A fork can install
  only packs without checks.
- Chosen: neither, answered by hh-advise under `/hh-supervise`, because the
  fork's own commits are combat cards, compendium items and the seams the
  importer module uses. Reading books from PDFs is the importer's work, and
  `foundry-modules` releases modules, not a system with its own release
  workflow.
- Rejected: `rpg-pdfs`, because no PDF is read here; `foundry-modules`, because
  the fork releases through its own `fork-release.yml`.
- Commits: the commit that adds this entry
- CC_NO_DOC: `rulesync.jsonc` lists the rules installed, and a change of packs
  is made only through `/hh-rules`, which asks again.
